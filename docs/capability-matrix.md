The **current executable interoperability profile** is KERI/CESR 1.0 JSON (`KERI10JSON`), text CESR attachments, Ed25519/BLAKE3 reference vectors, and KEL/TEL/ACDC/EXN/IPEX coverage as indicated below. The selected first foundation release profile extends that path with the required workflows in the table below. V2, native bodies, binary message transport, CBOR/MGPK bodies, and Signify/KERIA agent interoperability are explicit later-profile exclusions. Existing public primitive code tables remain available but do not imply end-to-end support for those profiles. The prior [parity ledger](keripy-parity/ledger.md) says “JSON-only, KERI/CESR v1 (permanent)”; its concrete corpus scope is retained, while “permanent” is not a protocol policy.

An item marked required is a release condition, not a claim that it is already implemented. The status table below records the present code and the task that owns each gap. An excluded wire combination must return a typed unsupported-profile or unsupported-algorithm error at its public typed boundary; low-level version and primitive parsers may retain wider syntax without claiming that a typed message is valid.

The A17 **build profile** is separate from protocol-version support. Isolated
downstream manifests compile 19 declared host profiles and the same 19 for
`wasm32-unknown-unknown`: `cesr-rs` empty/default/b64/core/crypto/std-core;
`cesr-stream` alloc/default/async/std-async; `keri-events`
alloc/default; `keri-codec` alloc/default; and `keri-rs`
core/default/wire/std-wire/credential-verification. `b64` implies `alloc`,
`async` implies `std`, and `keri-rs` core does not pull `keri-codec`.
`keri-events` has no `internals` feature: its constituent-field constructors
are explicitly `new_unchecked`, and checked wire construction stays in the codec.
Production consumers do not enable `test-utils`. These target
checks compile only; focused host b64/async/core/wire tests execute separately.
See the [A17 matrix and size evidence](audits/2026-09-30-a17-matrix.md).

For A09, the selected *existing* KERI 1.0 JSON body writer and pinned keripy `SerderKERI` define compact wire syntax. Fixed CESR token fields still have their own grammar. The [executing JSON oracle](audits/2026-09-29-a09-oracle.py) pins writer-form escaped strings and raw UTF-8, negative/decimal/exponent numbers, duplicate-key and object-order rejection, and exact raw-byte verification. The Rust reader accepts RFC 8259 numeric spellings and exact large integers without floating-point normalization; writers emit the pinned canonical spellings. Opaque application anchors retain the broader RFC escape grammar (including valid surrogate pairs) as signed verbatim bytes, while SAD/IPEX payloads require the pinned writer's string spelling. Every object rejects duplicate decoded keys; both walks are iterative and the public typed V1 reads now require explicit caller field and depth limits. RFC 8259 excludes `NaN`/`Infinity`, which pinned Python keripy mistakenly emits and accepts; Rust deliberately rejects them. The first foundation release excludes other body serializations; future profiles may add them.
