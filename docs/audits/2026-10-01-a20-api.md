# A20 public API and vocabulary inventory

Platform: aarch64-darwin; baseline commit `de08a972`; A01–A19 worktree retained.

## Contracts and ownership

- The pinned executable profile is KERI/CESR 1.0 JSON against keripy `de59bc7d`; the [capability matrix](../capability-matrix.md) leaves later EXN/IPEX profiles to A24/A28. The published KERI 1.1 specification has a different exchange field domain, so moving these V1 wire-shaped types into a supposedly version-neutral event vocabulary would misstate their contract.
- The closed [#193 owner-driven redesign issue](https://github.com/devrandom-labs/cesr/issues/193) asks for a per-crate surface review and wire-byte stability. The user has since authorized redesign, removal of redundant surface, and no compatibility wrappers. This A20 change remains a focused `keri-events` vocabulary pass; codec import updates only follow the constructor rename, and canonical bytes stay under their existing oracle tests.
- `Exn` owns a pending digest-code or verified wire SAID, raw canonical `SadBlock` fields, and the exact V1 field domain. `Ipex*` currently combine route data with envelope builders and typed parsers in `keri-codec`; moving those structs alone would split each operation across crates, duplicate conversion code, and gain no domain decision owner. Keep them in `keri-codec` for this profile. A28 owns authenticated conversation decisions in `keri-rs` or its host, not these data wrappers.
- `IpexGrant::anc` retains the canonical signed body because the `Deserialize` trait returns an owned event and exact raw bytes are needed for embed-map SAID verification. Its typed parse is validation, not a second stored authority. Moving it to an owned `KeriEvent` would add allocation and require retaining the bytes as well.

## Confirmed surface defects and proposed repair

- `keri-events/internals` gates thirteen all-field constructors (`SadBlock`, `Acdc`, five KEL events, and six TEL events); `keri-codec` always enables it. Cargo features unify across dependents, so the gate cannot distinguish trusted callers. The bare `new` name also makes an unverified self-SAID look like a validated event. Rename these constructors to `new_unchecked`, expose them explicitly without a feature, and remove `internals` from manifests and the build-profile matrix. Keep wire decoding and builders as checked construction routes. Do not add compatibility aliases.
- The five KEL event structs and `KeriEvent` lack `Clone`, `Debug`, `PartialEq`, and `Eq` although their fields support them. Derive these directly, giving a consumer value comparison and a useful diagnostic without a new wrapper.
- Builders' dummy SAIDs are local serialization scratch and never returned as event values; `SerializedEvent` contains computed bytes/SAID. The EXN builder already models pending/verified SAIDs explicitly. A20 should document and test that construction does not leak a placeholder as authenticated data; a deeper serializer rewrite is not justified by this inventory.
- Lifetimes on the public event/EXN models track borrowed CESR matter and raw payload. `into_static` is an explicit ownership conversion. No independent lifetime can be removed without copying signed bytes or reshaping unrelated primitives; retain it and demonstrate borrowed-to-owned use in a consumer example.

## Ratchet-policy proposal

The per-module free-function ratchet usefully discourages diffuse public helpers, but it cannot measure associated methods, enum variants, ergonomics, or actual duplication. Keep it as a narrow guard, document task-level API review and consumer evidence alongside it, and lower budgets only when code is genuinely removed. No protected lint/config policy change is proposed in A20.

## Executed verification

The independent `keri-events` public API test compiles its unchecked `SadBlock`
constructor and the KEL value traits without relying on Cargo feature
unification. The `keri-codec` inception identity suite exercises typed wire
reading and signed fold rejection. The public `incept_aid` example executes a
checked builder, owned value comparison, byte-exact round trip, and typed SAID
tamper rejection. These focused checks, `cargo fmt --all --check`, and
`git diff --check` exited 0 on aarch64-darwin.

`nix flake check -L --option max-jobs 1` exited 0 on the A20 source. Release
Nextest executed 2,571 passing tests with 24 skipped; the isolated consumer
gate compiled all 18 host and 18 WASM profiles. Fuzz replay, examples, Clippy,
documentation, formatting, audit/deny, and the protected ratchet checks passed.
WASM behavior was compile-checked only. Nix omitted incompatible
aarch64-linux, x86_64-darwin, and x86_64-linux systems.
