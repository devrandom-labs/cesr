## Semantic and ownership inventory

- KEL `Signed::from(&EventMessage)` copies parsed controller `sigs` and witness `wigs`; TEL `SignedTel::from(&TelMessage)` copies controller and backer slices. `from_host_asserted_parts` intentionally takes owned vectors for hosts that retain evidence after the parsed message is gone. Both constructors preserve the event/body binding and exact signed bytes. `KeyState::verify_exn` and `TransferableEndorsement::from(&TransferableReceipt)` already borrow their signature slices.
- `Authority::verify` resolves every role-wrapped key by cloning its `Matter`, verifies *all* supplied signatures, then sorts/deduplicates only their valid **indices** before checking the threshold. `Verified::sigs()` currently retains repeated valid signature references. `Witnessing::receipted_by` also clones every key and verifies all receipts before index dedup. Transferable `ReceiptedEvent::endorsed_by` clones keys, verifies all signatures, and requires at least one valid signature; unlike KEL and witness batches, an out-of-range receipt index is an error checked across the entire group before any crypto. TEL `RegistryState::authenticate_backer` clones each backer prefix into a `VerifyingKey` and then takes the same `Authority` path, causing another full key clone.
- Pinned keripy `verifySigs` (`/tmp/cesr-a07-keripy-pin/src/keri/core/eventing.py:305-350`, commit `de59bc7d834955c5b0273c62f6b8b6a0df150dc3`) deduplicates the full qb64 signature *before* verification. Therefore exact duplicate signatures can be skipped before crypto, but two signatures sharing an index with different raw bytes must each have a chance to verify: an invalid first signature cannot suppress a valid later one. The local `Siger` `PartialEq` also compares optional attached `verfer`, so full wire-material equivalence must compare code, index, ondex, and raw signature bytes explicitly, ignoring that local attachment.
- Current-key `index` and prior-next `ondex` are separate. A valid current-only signature (`ondex=None`) authenticates its current authority but exposes no prior-next commitment; a dual-index signature with the same index and an appropriate ondex can still open it. Dedup by index before commitment checking would lose this case. Commitments count distinct *matching ondices* after digest verification. Existing transition tests cover reordered reveals, out-of-range ondex, and duplicate ondex; A10 adds same-current-index, different-ondex adversarial tests.
- Numeric thresholds count distinct verified current indices here, with documented conservative divergence from a keripy duplicate-ondex corner case. The optimized path must retain this fail-closed rule, preserve weighted-threshold positions, and use each previously deduplicated index set without another sort/dedup.
