# A13 encoding baseline and direct-write evidence

Platform: aarch64-darwin, commit `de08a972` plus uncommitted A01–A12 work. Rust release profile; 31 executed process-local timing samples after four warmups. Timings are per 10,000 primitive encodings or 1,000 representative inception serializations and include output allocation. They are machine-local observations, not stable performance promises.

The [CESR specification](https://trustoverip.github.io/kswg-cesr-specification/) requires URL-safe Base64, no `=` post-padding, right-aligned values, and zero lead bytes/pad bits. The existing code tables and pinned keripy fixture remain authoritative for each supported code. `Matter::to_qb64b` previously allocated a padded copy plus output; `Indexer::to_qb64` materialized two index strings, a formatted header, padded raw bytes, a Base64 string and a formatted result. The JSON `Encode` path materialized each `Matter` as a qb64 `String` before copying it to the event buffer. These are confirmed against current source; no compatibility requirement applies to internal writer shape.

Before commands: `cargo test --release -p cesr-rs --test a13_encoding -- --ignored --nocapture` (`/tmp/cesr-a13-primitive-before.log`); `cargo test --release -p keri-codec --test serder_allocation serialize_release_measurement -- --ignored --nocapture` (`/tmp/cesr-a13-serialize-before.log`). The new `primitive_qb64_allocates_only_its_result` regression **failed before** the change at Matter allocation count 2, then passed after the change. After commands are identical, with `-after.log` paths. All timing runs executed, not compile-only or cached. The representative JSON improvement is demonstrated by allocation count; this short timer run alone does not establish a significant end-to-end latency change.

The implementation uses one crate-private zero-lead Base64 block writer for Matter and Indexer. Both append directly to an existing byte buffer, preserving source bytes, CESR alignment and optional caller capacity. JSON `Encode` appends quoted Matter bytes in place and adjacent ACDC/EXN/IPEX fields reuse their existing `Encode` implementation. The owned convenience methods now call the same append path. The old padded-copy and intermediate-header algorithms are removed; no compatibility facade was added. `to_qb2` and SAID slot patching still construct qb64 temporaries and will be assessed against measured scope before A13 is closed.

The separate owned-key prototype (`cargo test --release -p cesr-rs --test a13_encoding owned_key_representation_measurement -- --ignored --nocapture`, `/tmp/cesr-a13-owned-key.log`) executed 31 construction samples of 1,024 Ed25519 key values. An owned `Matter<VerKeyCode>` occupies 56 bytes per vector slot and, with its raw `Cow` owned, requested 90,112 bytes in 1,025 allocations. A prototype `(VerKeyCode, [u8; 32])` occupies 33 bytes per slot and requested 33,792 bytes in one allocation. Construction medians were 13,541 ns versus 1,708 ns (p10–p90 13,250–18,167 and 1,667–1,750). This is a storage prototype, not a wire-compatible replacement: generic `Matter` supports variable-size codes and borrowed data, and the profile-dependent crypto algorithms are still under A24. Replacing that carrier here would add an algorithm-specific wrapper layer without settling its model. The evidence is retained for the later representation decision.

Verification: `cargo test --release -p cesr-rs --lib core::matter --quiet` passed 529/529 and `core::indexer` passed 277/277; `cargo test --release -p cesr-rs --test a13_encoding` passed 4/4, with two explicit release benchmarks ignored by that ordinary run and executed separately above. The boundary test covers all 16 indexed code classes and the zero/one/two-lead small and large variable Matter classes; typed parser regressions reject nonzero lead bytes and pad bits. `cargo test --release -p cesr-stream --all-features --lib keripy_diff -- --nocapture` executed six tests: 50 Matter and 53 Indexer pinned vectors with zero skips, plus stream and both counter sets. `cargo test --release -p keri-codec --all-features --lib keripy_parity -- --nocapture` executed 22 tests, including 43 event assertions and byte-identical reserialization; the corpus's unrelated ledger exclusions remain declared. `cargo test --release -p keri-codec --all-features --test serder_allocation` passed both ceiling tests (one benchmark skipped there and executed separately). Targeted all-feature Clippy, rustfmt and `git diff --check` passed.

The first full `nix flake check -L --option max-jobs 1` stopped at `cesr-fn-ratchet` because the shared new `pub(crate) fn` raised `b64` from six to seven free functions. No policy budget was raised. The encoder became the method of a crate-private borrowed `ZeroLead` value, so the ratchet stayed at six. The second full invocation **passed** (`/tmp/cesr-a13-flake2.log`) on aarch64-darwin: Nextest executed 2,528/2,528 tests across 34 binaries with four explicitly ignored release benchmarks; the three A13 benchmark functions were executed separately as documented above. Twelve checks built/passed in the final run, including Clippy, formatting, documentation, doctests, fuzz replay, ratchet, no_std and WASM **compile-only**. Eight other checks reported `previously built` (YAML, TOML formatting, nixfmt, audit, deadnix, shellcheck, actionlint, KERI boundary). The flake omitted incompatible aarch64-linux, x86_64-darwin and x86_64-linux systems. No outcome is claimed for those platforms.

Remaining product-level representation choice: the inline-key prototype is evidence for later profile-aware state storage, not a change to generic `Matter`. A13's own acceptance criteria are met.
