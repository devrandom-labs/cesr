# A14 incremental framing contract and baseline

Platform: aarch64-darwin, baseline commit `de08a972` with A01–A13 uncommitted changes. A14 is accepted on the final worktree described below; profile-dependent V2/native-body capabilities remain A24/A25 work.

The [CESR stream parsing rules](https://trustoverip.github.io/kswg-cesr-specification/) require a cold-start domain discriminator and, for interleaved JSON/CBOR/MGPK mappings, a version string as the first field so the body length can be known without deserializing it. CESR count-code groups are self-framing. Repository [#208](https://github.com/devrandom-labs/cesr/issues/208) requires typed incomplete versus malformed errors; [#210](https://github.com/devrandom-labs/cesr/issues/210) records the owned-Bytes versus borrowing tradeoff and V1/V2 read inconsistency. [#193](https://github.com/devrandom-labs/cesr/issues/193) reserves the general per-crate API redesign for owner direction. The user's current A01–A30 mandate and subsequent design/no-compatibility direction authorize the scoped A14 framing contract, without treating unrelated #193 surface proposals as automatic work.

Current behavior is split across layers. `CesrMessage::parse` detects the cold start and body length, but its `Event` variant exposes a lazy `Groups` iterator over *all* remaining input and does not identify a complete attachment boundary or return a consumed remainder. For a short JSON prefix such as `{`, its 100-byte version search returns `MissingVersionString` immediately, conflating incomplete with malformed. `Message::parse` reparses that head and consumes all complete adjacent CESR groups, returning the next non-CESR byte as remainder; a complete body with no currently buffered attachment bytes is accepted immediately. That last outcome cannot be made chunking-independent for an open stream because another attachment group might arrive next. `CesrCodec<V>` is an async adapter for *groups*, not full messages: it preserves `BytesMut` on `NeedBytes` and slices complete quadlet groups, but reruns element-count framing from the first byte on each partial poll. `OpaqueScan`/`Scanner` are iterative and avoid stack overflow, yet their field and nesting work is bounded only by the available input length. The version size field itself admits a much larger body than an application may wish to buffer. None of these entry points currently receives a caller work policy.

Proposed deterministic contract for A14 implementation: one sans-I/O frame cursor advances monotonically over caller-owned bytes, with a supplied policy for body bytes, attachment bytes/group count, signatures, fields and nesting. A self-framed bare attachment may emit as soon as complete. A message body followed by unframed attachments may emit only at an unambiguous next top-level body boundary, a complete enclosing attachment-length frame, or explicit end-of-input; on an open stream a body alone remains pending. Body-complete/attachment-incomplete remains pending. Explicit end-of-input converts an incomplete head/body/group into a typed truncation error and flushes a complete final message. Malformed input and policy exceedance are typed errors. Every successful emission consumes at least one byte and reports the exact remainder. This EOF rule is an inference from CESR self-framing plus the absence of a terminator for an arbitrary run of adjacent attachments; it must be tested against the pinned keripy fixture and current public wire routes before finalizing the API. The async adapter should retain the same cursor and only provide buffer/I/O integration, with no separate grammar.

The fixture is one `ControllerIdxSigs` element-count group containing repeated 88-byte signatures. Each bytewise sample appends one byte and calls `decode`, asserting `None` until the final byte. The coalesced sample calls `decode` once on the same frame. No sockets or scheduling are involved.

## A14.2 partial regressions and group-cursor implementation

Focused red cases were executed before their fixes: valid truncated JSON version prefixes incorrectly returned `MissingVersionString`; a later JSON `v` was accepted; a zero declared body returned success with no progress; and `CesrCodec::decode_eof` returned a generic I/O error for a partial counter rather than typed truncation. The JSON tests are in `message.rs`; the EOF and every split of a two-group stream (with exact remainder) are in `codec.rs`. The latter split test passed after the cursor change. The EOF case failed before its fix, then passed. The group fragmentation release measurement above is the pre-fix work regression.

The group frame-length table now initializes a `GroupFrameCursor` with the counter and kind-specific `skip` function. It retains the offset after each complete element and retries only the current incomplete element on new input. One-shot `frame_len_v1/v2` and the async codec use this same table. The async codec no longer has separate V1/V2 quadlet mappings and decode branches; it splits exactly one completed frame and invokes the existing group construction parser. This still performs one final element pass to construct the owned group, but removes the repeated completed-prefix passes on every fragment. `decode_eof` maps an incomplete final group to `ParseError::Truncated { missing }` without consuming its bytes.

The same explicitly executed release benchmark after the cursor change is `/tmp/cesr-a14-group-after.log` (4 warmups + 31 samples per cardinality, aarch64-darwin, `--features async`). Bytewise medians for 1/16/64/256 signatures were 1,875/28,250/93,209/335,334 ns. At 256 signatures this is 59.2× faster than the 19,834,750 ns pre-fix median; at 64 it is 17.3× faster. Input grows 4× from 64 to 256 signatures and bytewise time grows 3.6×, consistent with linear framing over this fixed-size signature family. This is a scoped measurement, not a proof for nested variable-sized elements; a bounded element policy remains required.

A14.2 remains incomplete: red outcomes for body-complete/attachment-partial and EOF, hostile length/count limits, signature/field/depth budgets, and full-message chunking still need to be added before the bounded message decoder is accepted.

Specification correction during A14.2: the first field requirement does not mandate byte-exact compact `{"v":"` spelling. A red case with JSON whitespace between first-field tokens failed under the initial strict-prefix fix. `CesrMessage::parse` now walks only the first `v` token and permits the four JSON whitespace bytes around the key and colon; it still rejects a different first key and returns `NeedBytes` for a valid partial prefix. `cargo test -p cesr-stream --lib message::tests -- --nocapture` executed 13/13 passes. ## Partial sans-I/O V1 message framer

`MessageFramer` now holds offsets, a persistent JSON first-field cursor and the same `GroupFrameCursor` used by the group codec; the caller owns and extends the byte prefix. `FrameSpan` identifies exact body and total lengths. The explicit `FrameLimits` currently enforce declared body bytes, attachment bytes, top-level attachment-group count and element count per group. A body alone on an open stream remains pending; a complete bare group or `-V` envelope emits immediately; unframed attachment runs end at the next body cold start or explicit EOF. The `MessageCodec` async adapter delegates to this framer and yields a `Bytes` frame without parsing the body. The one-shot KERI parser still consumes attachments directly; its integration and signature/JSON budgets remain open.

Focused tests cover every split of a body plus signature group plus next body (exact consumed remainder), body-only open versus EOF, partial attachment EOF truncation, complete `-V` and bare group immediate emission, oversized declared body and group element count before payload buffering, 512 bytes of fragmented JSON header whitespace and its configured body-byte cutoff, and async adapter retention of exact bytes. `cargo test -p cesr-stream --all-features` executed 373 unit passes, one ignored release benchmark, two integration passes and one compile-fail doctest (`/tmp/cesr-a14-stream-tests.log`). `cargo test -p keri-codec --lib message::tests` executed 30 passes (`/tmp/cesr-a14-keri-message-tests.log`). `cargo check -p cesr-stream --no-default-features --features alloc` compiled successfully; it did not execute on WASM. All-feature cesr-stream Clippy passed with `-D warnings`, apart from the existing upstream test-only config warning. No full A14 Nix gate has run.

Open design work is substantive: first-field CBOR/MGPK partial/malformed behavior, limits on incomplete attachment counter heads, nested group and total signature counts, JSON field/depth work in the body codec, pinned keripy fixture equivalence, variable-element hostile scaling and a public `keri-codec` integration route using the bounded framer. V2 interleaved-message coverage must be governed by A24's versioned matrix. These are acceptance gaps, not optional exclusions.

## Nested-signature fragmentation work

The completed-element cursor still retried an incomplete `-F`/`-H` element from its first primitive on each fragment. These families contain a variable-length nested `-A` signature list. An explicitly run release probe, `cargo test --release -p cesr-stream --lib bench_bytewise_nested_signatures -- --ignored --nocapture`, measured three bytewise passes through one bare `-F` element: 5,772 bytes / 64 nested signatures took 8.51 ms; 22,668 bytes / 256 nested signatures took 60.29 ms. This confirms repeated work within an element, separate from the earlier top-level group finding. The probe is ignored during ordinary test gates and uses one timing observation, not a stable benchmark distribution.

`NestedSigCursor` now retains the offset after each complete Matter, nested counter and signature. Both `GroupKind::skip` and the incremental group framer use this grammar, so no second nested scanner was added. The framer caps the input slice to the attachment-byte budget even when the caller supplies a coalesced oversized buffer. An executed release rerun of the same probe measured 0.232 ms (64) and 0.746 ms (256) for the same three passes: about 36.6× and 80.9× faster respectively; 4× the bytes takes 3.2× the time. A normal regression checks every two-way split, bytewise delivery, exact bare-group span/remainder and final-byte truncation for both `-F` and `-H`.

A further **red** regression supplied only a nested `-A` counter declaring two signatures while the configured group-element budget was one. The framer incorrectly waited for the signature payload; it now rejects at that counter with `LimitExceeded { kind: GroupElements, limit: 1, actual: 2 }`. The green regression covers both `-F` and `-H` outer families. This is a per-group nested element cap; total signatures across groups and inside quadlet-counted envelopes remain open.

After the nested-counter bound, `cargo test -p cesr-stream --all-features -q` **executed** 382 unit passes, two ignored release probes, two integration passes and one compile-fail doctest. `cargo clippy -p cesr-stream --all-features --lib --tests -- -D warnings`, `cargo check -p cesr-stream --no-default-features --features alloc` (**compile-only**), and `git diff --check` passed. Clippy still emits the pre-existing config warning about the test-only `Matter::new_unchecked`. A14's total-signature, nested-envelope, JSON field/depth and public read-route budgets, target/oracle breadth and fresh Nix gate remain pending.

## Signature and attachment-envelope policy, partial

A **red** framer regression showed that direct `-A` declarations, nested `-F` declarations, and a second signature-bearing group after an earlier one could exceed an intended one-signature policy without rejection. A second **red** regression showed that a complete `-V` attachment envelope could conceal two `-A` signatures behind the same policy. `FrameLimits` now has `max_signatures`, `max_nested_groups` and `max_nesting_depth`; `GroupFrameCursor` counts declared direct signatures in `-A`, `-B`, `-C` and `-D` and the nested `-A` lists in `-F`/`-H`. The V1 framer scans a complete `-V` payload once, counting its child groups/signatures and nested `-V` depth with an explicit stack. It rejects a count over budget at its counter, before the corresponding signature payload is needed. The bounded scan uses the existing group counter/element grammar; it does not construct a second parser.

`cargo test -p cesr-stream --all-features -q` **executed** 385 unit passes, two ignored release probes, two integration passes and one compile-fail doctest. `cargo test -p keri-codec --test a14_framing -q` **executed** two pinned KEL chunking tests. All-feature stream Clippy passed with `-D warnings` and the existing test-only config warning; no full Nix gate has run. The release nested-signature probe was rerun with its fixture policy raised to the measured count (the first rerun correctly failed because the new default four-signature policy rejected the 64/256-signature fixture). It measured 0.386/1.353 ms for three bytewise passes over 64/256 nested signatures, still 22.0×/44.6× below the original pre-cursor 8.51/60.29 ms observations. Generic and other opaque quadlet payloads are not yet traversed by this V1 `-V` policy walk; field/depth limits in the KERI JSON body scanner and the public bounded read route remain open. `FrameLimits` fields and current scope are recorded in the stream changelog; this is not A14 acceptance.

The [CESR Annex A override rule](https://trustoverip.github.io/kswg-cesr-specification/#universal-code-table-genus-version-codes-that-allow-genus-version-override) identifies three universal enclosing groups that may switch genus/version when the first inner code selects another table: generic pipeline, message-plus-attachments, and attachments-only. Their current V1 table counterparts are `-T`, `-U`, and `-V`; V2 uses `-A`, `-B`, and `-C`. At this stage the V1 policy walk only descended `-V` and assumed V1 for its children. The next change shares table-switch handling with the existing `UnwrapGeneric` path rather than treating arbitrary opaque quadlet bytes as V1 groups.

## Public typed read policy, partial

A public `KeriEvent::deserialize(body, JsonLimits::new(1, 64))` regression first failed to compile because the old trait offered no policy. The trait now requires `JsonLimits`, which travels into the actual KEL/TEL/receipt/EXN/ACDC scanner. `MessageLimits` combines `FrameLimits` and `JsonLimits` for every public typed message parser. The message parser first asks `MessageFramer` for one exact frame, then dispatches its body and routes only that frame's attachment region; it no longer reparses the cold start via `CesrMessage::parse`. There is no unlimited compatibility overload. IPEX typed lifting and offer/grant validation receive JSON limits as well. The codec changelog names the breaking migration. At final input, incomplete frames now return `Truncated`, matching the A14 EOF contract; three old tests expecting `NeedBytes` were updated to assert that desired behavior.

Pinned public fixtures establish successful generous-policy reads and typed tight-policy rejection for KEL, TEL, receipts, EXN and ACDC. A body-byte policy on `EventMessage::parse` rejects before body parsing.
