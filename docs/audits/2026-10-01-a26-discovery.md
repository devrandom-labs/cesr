# A26 V1 discovery contract and implementation ledger

Baseline: `de08a972` plus accepted A01–A25 worktree. A24 selects V1 JSON
query/reply and key-state discovery for the first foundation release.

## Source and prior-scope reconciliation

The pinned [KERI routed-message section](https://github.com/trustoverip/kswg-keri-specification/blob/fbdd4a6155e48248873cccd5cf6f79b6b631a021/spec/spec-body.md#L913)
requires `qry` and `rpy` with route fields. Its V1 field-order rule gives
`qry` as `v,t,d,dt,r,rr,q` and `rpy` as `v,t,d,dt,r,a`. Nearby examples use
top-level `i` and a V2 `KERIC...` version string. Pinned keripy
`eventing.query`/`reply` and `SerderKERI.Fields` confirm the split: V1 omits
top-level `i`; V2 includes it. In V1, the authorizing AID is supplied by a
nontransferable signer couple or transferable signature group with its
historical establishment seal, rather than an unauthenticated body field.

Issue #82's prior 1.0 scope deliberately rejected `qry`/`rpy` from
`MessageType` as application routing. Its subsequent TEL/EXN revision
already recognized that `MessageType` names wire `t` values while body and
application decisions can live elsewhere. A24 now explicitly requires
V1 query/reply for discovery and state exchange. Therefore A26 revises the
prior exclusion: `MessageType` will name `Qry` and `Rpy`; fixed wire grammar
and SAID/attachment parsing belong in `keri-codec`; route acceptance belongs
in a pure protocol decision layer; fetching, caching, network routing and
storage remain host work. This is a recorded contract change, not an
unnoticed reinterpretation of #82.

The pinned [OOBI section](https://github.com/trustoverip/kswg-keri-specification/blob/fbdd4a6155e48248873cccd5cf6f79b6b631a021/spec/spec-body.md#L2627)
states that an OOBI URL or unsigned `/oobi` reply is only a discovery hint;
material returned from it needs in-band verification. Pinned keripy's
`Kevery` routes include `/end/role/{add,cut}`, `/loc/scheme` and
`/ksn/{aid}`. Its `Revery.acceptReply` uses historical signer evidence,
threshold verification and a pairwise later-than rule: greater
establishment sequence wins for transferable signers; equal sequence
requires later reply timestamp; nontransferable signers require a later
timestamp. The Rust decision must also reject supplied contradictory
evidence as terminal and expose absent evidence as awaiting, following the
foundation's established trust-boundary policy.

## Executed reference and red Rust evidence

`scripts/keripy_discovery_oracle.py` imports exact keripy
`de59bc7d834955c5b0273c62f6b8b6a0df150dc3`, verifies its import path,
and checks the seven-case `corpus/discovery/v1.jsonl` against live factories.
Cases cover `/logs` query, endpoint-role add/cut, transferable and
nontransferable location replies, a key-state notice built from a real pinned
inception, and an intentionally unsigned OOBI hint. Transferable signed cases
use a deterministic Ed25519 key and keripy `messagize` with a `SealEvent`
source; the nontransferable case uses a distinct pinned Ed25519 key and a
`-C` couple. Their bodies, SAIDs,
signatures and attachment bytes come from the reference rather than Rust
shape reproduction. The `--write` generation and default comparison both
exited 0 under Python 3.14.6 with the pinned checkout. The fixed reference
inception and signer establishment coordinate are included in each signed
row for historical-authentication tests.

`nix develop --command cargo test -p keri-codec --test a26_discovery`
failed as expected before implementation with
`UnknownMessageType("qry")`. The test first verifies each raw body's SAID
using the generic public SAD verifier, then requires `MessageType` and
`Message::parse` to accept the exact V1 body and framed form. A26.2 now
passes all seven fixtures as `Message::Routed`; `RoutedBody` checks strict V1
field order, canonical payload, declared size and SAID, and renders every
fixture byte-exactly through `write_query`/`write_reply`. `RoutedMessage`
retains exact signed bytes, nontransferable couples and transferable signer
groups with historical establishment `(prefix,sn,SAID)`; it deliberately
claims no authentication until the protocol judgment runs. Tests reject a
V2 top-level sender, body tampering and malformed writer inputs, and check
the framed remainder.

## Pure decisions and host boundary

`keri::DiscoveryJudge::reply` receives the parsed message, accepted historical
signer KEL state, optional accepted KSN subject state and the previous durable
`ReplyVersion`. It checks route/payload owner, attachment signer AID and
historical seal `(sn,SAID)`, then verifies the signature threshold over the
exact body. A nontransferable `-C` signer verifies directly against its key
prefix. It converts RFC-3339 timestamps with offsets to UTC nanoseconds and
applies the pinned later-than rule: higher signer establishment sequence or,
at equal sequence, later timestamp. `MissingSignerState` and
`MissingSubjectState` are awaiting evidence; wrong signer, contradictory
evidence, bad signature and stale/replayed reply are terminal. The selected
`/ksn/{aid}` notice is compared against the accepted KEL snapshot's
identifier, latest coordinate/ilk, controller and next-key authority,
witness set/threshold, config, delegator and last establishment. The
`/logs` query has its own authenticated requester/target judgment.
KSN `p`, `f` and `dt` are parsed as signed report metadata, but the
`KeyStateSnapshot` does not hold the host's first-seen timestamp/ordinal or
the latest event's prior SAID, so this judge does not assert an independent
match for those three fields. Hosts needing those report claims must compare
them with their own accepted event record and observation metadata.

An unsigned `/oobi/witness` body yields `UntrustedHint`; no trust state is
created by a URL or SAID. Fetching, cache, route transport, historical KEL
lookup and atomic persistence of resource update plus `ReplyVersion` are host
work, documented in [the integration contract](../discovery-integration.md).
Focused tests verify all seven reference bodies, read/write byte equality,
framed remainders, two signer forms, valid judgments, missing KEL evidence,
wrong route owner, bad signature, absent KSN subject, stale replay and a
later accepted marker. The core unit test proves a KSN with false keys or
last-establishment sequence disagrees with the accepted snapshot. All-target
Clippy with `-D warnings` passed for the three touched crates before the
full gate.
