# A12 registry cardinality baseline and design contract

Platform: aarch64-darwin, Rust 1.95.0, `--release`, default `keri-codec` features. Current commit: `de08a972b390ea640519d4dcb7343d5dc4a864b9` plus uncommitted A01–A11 work. Executable case: `registry_cardinality_baseline` in `crates/keri-codec/tests/a10_auth_work.rs`. It creates a real backerless `vcp`, a contiguous issuer KEL with one exact TEL seal per distinct `iss`, then validates each issuance through `RegistryState::ingest_mut`. All event construction and anchoring occur before the measured ingestion loop. Each status batch makes 10,000 deterministic pseudorandom lookups among the accepted credentials. Replaying the last accepted event tests late chain rejection; removing its accepted KEL anchor tests early evidence rejection. The counting allocator records calls, cumulative requested bytes and live-byte delta relative to the empty registry. No fixture data is included in the live delta; an O(1) temporary signed carrier remains in scope at each sample.

Executed after compilation: `target/release/deps/a10_auth_work-af44d69e79a389c7 registry_cardinality_baseline --ignored --exact --nocapture`, 31 separate processes, all passed. All 10,000-lookup batches allocated 0 bytes; all replay and missing-anchor rejections allocated 0 bytes. The missing-anchor case runs before chain lookup and is beneath the timer's single-call resolution (median 0–42 ns), so the replay case is the useful cardinality-dependent rejection sample. The live-byte delta includes a fixed small signed-carrier overhead and the registry's growing credential vector; it does not count the fixture event objects that the registry also borrows, so it understates total host-retained history. The cumulative issuance and random lookup trends match the two linear scans in `record_chain_event` and `vcstate`; inserting N distinct credentials does O(N²) total lookup work. Timings are comparative, not a wall-clock acceptance threshold.

## Protocol and repository contract

The [PTEL draft](https://trustoverip.github.io/tswg-ptel-specification/draft-pfeairheller-ptel.html) distinguishes a **management TEL** (`vcp`, `vrt`) from a **separate VC TEL** (`iss`, `rev`, `bis`, `brv`) for each credential. Management state is the registry identity, issuer and ordered backer configuration; a credential TEL has its own identifier, sequence and prior digest. Backed credential events name historical management state through `ra`, so current backers cannot stand in for a past backer list. The [KERI specification's seal semantics](https://trustoverip.github.io/kswg-keri-specification/) require the external TEL event to be bound to its accepted KEL seal. Pinned keripy `Tever` combines transition routing with its database, but its architecture is not the host boundary here.

[Issue #98](https://github.com/devrandom-labs/cesr/issues/98) requires a pure sans-I/O TEL fold with host-owned lookup and persistence. [Issue #92](https://github.com/devrandom-labs/cesr/issues/92) dissolved the proposed core `KelProvider` in favor of host-supplied evidence and owned snapshots; it applies to KEL, but the same explicit evidence boundary is appropriate for TEL. [Issue #193](https://github.com/devrandom-labs/cesr/issues/193) reserves general per-crate redesign decisions for Joel; A12 is the concrete registry defect explicitly authorized by the current work request, not that wider review. The user further clarified that source compatibility is not a requirement and asked to remove redundant wrappers where a better canonical API replaces them.

Design for A12.2/A12.3: make `RegistryState` an **owned management head** with no credential collection; give each credential its own **owned** chain head keyed by `(registry SAID, credential SAID)`. The host retrieves only that head and the governing accepted management head (plus historical management state at `ra`), then persists the accepted result. The validating transition checks issuer/registry identity, KEL anchor, event flavor, backer authority, sequence and prior digest before mutating or returning the new head. Historical management evidence should be an accepted management state, not a second redundant snapshot wrapper. Registry and credential states must contain owned primitives, not references into the full input event history. Rejected delivery must leave both records unchanged. No map, lookup trait, database, clock or runtime enters the core. This is a replacement of the unbounded aggregate API, not an additive compatibility facade.

## A12 post-split measurement

The old ignored baseline case above was replaced in source by `registry_cardinality_after` after the split; the pre-split raw log preserves its executed result. The new case builds the same 1,025 distinct issuance/KEL fixtures outside measurement, calls `CredentialState::incept` for the first 1,024, and stores the owned heads in a **test-only host `HashMap<String, CredentialState>`**. It measures core validation separately from the host map insertion. Random reads and replay occupancy checks use precomputed keys, so the timed lookup itself does not encode a key. A missing KEL anchor on the next candidate is the rejected-delivery sample. The live-byte delta is measured after fixture construction and registry inception; it includes the host map, all owned heads and a fixed temporary carrier, but excludes the fixtures. This is a concrete host option, not a prescribed production store.

`cargo test --release -p keri-codec --test a10_auth_work registry_cardinality_after -- --ignored --exact --nocapture` compiled and passed; its release test binary was then run in 31 separate processes with `registry_cardinality_after --ignored --exact --nocapture`, 31/31 passed. The first four runs were discarded. Raw output: `/tmp/cesr-a12-after-31.log`. Medians and p10–p90 below are from the remaining 27 runs.

At 1,024 credentials, core plus host issuance totals 221,852 ns median, about 6.1× less than the old aggregate's 1,344,100 ns. The 10,000 random reads are about 62.9× faster at that count. More telling than those machine-specific ratios: the core incurs exactly **3 allocations and 96 requested bytes per accepted credential**, and the map's lookups allocate 0; neither cost grows with unrelated credential count. Replay occupancy checks allocated 0 and had a median 42 ns at every count. Missing-anchor rejection allocated 0 and had a median 0–42 ns, below single-call timer resolution. The test host store's live memory is *larger* than the old aggregate vector alone (637,288 vs 49,504 bytes at 1,024) because it owns three SAIDs per head and pays hash-table/key overhead. Those figures are not apples-to-apples total host memory: the old borrowed aggregate also required all 1,024 source TEL events to remain live, and that fixture memory was excluded from its 49,504-byte delta. The new state can release every source event after acceptance, proved by the direct owned-state regression. A13 will examine owned primitive representation; A12 makes no claim that this particular hash table is the memory-optimal host choice.
