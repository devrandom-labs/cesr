# A17 standalone feature baseline

Platform: aarch64-darwin, Rust 1.95.0, commit
`de08a972b390ea640519d4dcb7343d5dc4a864b9` plus the worktree in
`docs/TODO.md`. The executable matrix is `scripts/check_feature_matrix.py`.
Each row creates a temporary downstream crate with exactly one path dependency,
disables its default features, and runs `cargo check --offline` in a separate
Cargo invocation. This avoids workspace dev-dependency feature unification.

The first invocation, `python3 scripts/check_feature_matrix.py`, exited 1:
10/14 profiles compiled. `cesr-rs` with `b64`, `core`, or `crypto` failed because
`b64` used `String` and `Vec` without enabling `alloc`; the `b64`-only build also
found an undeclared `base64` dependency and a core-only helper. `cesr-stream`
with `async` failed because Tokio's decoder error requires `std::io::Error`.
The standard/default-like and alloc-only profiles masked these mistakes.

After making `b64` imply `alloc`, keeping the `base64` dependency in `core`,
gating the core-only helper, and making `async` imply `std`, the same command
exited 0: all 14/14 profiles compiled. This was compile-only evidence. The
matrix also covers the `keri-rs` core with no `wire`, its `wire` profile, and
both alloc-only and `internals` profiles of `keri-events`. A separate direct
`cargo check -p keri-events --no-default-features --lib` failed in `cesr-rs`
because that configuration does not provide `alloc`; `keri-events` needs
`alloc` or `std`, as its manifest and public types imply. The alloc-only
standalone consumer passed. A17.2 will make these guarantees explicit in CI;
A17.3 will update public documentation and measure binary/dependency sizes.

## Isolated host and WASM gate

The checked-in matrix now also reads Cargo's resolved features for each
downstream manifest. It fails if production consumers enable `test-utils`,
if core-only `keri-rs` pulls the wire codec or `internals`, if b64-only cesr
pulls core/crypto, if alloc-only stream pulls crypto, or if a declared
no_std profile pulls `std`. `python3 scripts/check_feature_matrix.py`
passed 14/14 on the host. `nix develop --command python3
scripts/check_feature_matrix.py --target wasm32-unknown-unknown` passed
14/14 compile-only WASM profiles. The Nix `cesr-nostd` and `cesr-wasm`
derivations each ran the corresponding script and exited 0; WASM code was
not executed. Host runtime checks executed 175 b64 tests, 28 async-codec
tests (one ignored), and 73 `keri-rs` library tests in each of the core and
wire profiles. Workspace test runs can unify dev features, so the independent
consumer builds establish isolation.

Adding each crate's literal default profile exposed a separate dependency
leak. The first 19-row host invocation and the corresponding Nix `cesr-nostd`
check failed because default `keri-rs` resolved `keri-codec` and
`keri-events/internals`, despite its sans-I/O default contract. The all-feature
Nextest in that failed Nix attempt still executed 2,567/2,567 passing tests
with 24 skipped; it did not prove the default dependency boundary. Removing
the redundant `keri-codec` dev-dependency alone was insufficient; the weak
`keri-codec?/std` edge in the `std` feature still activated the codec in this
resolved graph. Removing both edges kept codec support behind `wire` and made
the isolated host and WASM matrices pass **19/19** each, including five literal
default profiles. Final full Nix gate evidence is recorded in `docs/TODO.md`.

## Dependency and WASM size probes

`python3 scripts/measure_feature_size.py` builds three independent consumer
`cdylib` probes for `wasm32-unknown-unknown` with opt-level 3, LTO, one
codegen unit, stripped symbols and aborting panic. The core probe encodes a
Matter, the Ed25519 probe signs and verifies, and the salty probe also derives
an Ed25519 key through Argon2id. Cargo metadata counts resolved packages
for that target. These linked sizes are representative workloads, not whole
crate sizes or a production application benchmark.

| Probe | Resolved packages | Argon2 resolved | Linked WASM bytes |
| --- | ---: | --- | ---: |
| CESR core | 57 | no | 16,264 |
| CESR Ed25519 sign/verify | 82 | yes | 451,937 |
| CESR salty derivation + sign/verify | 82 | yes | 496,379 |
| KERI core without wire | 84 | yes | not linked |
| KERI core with wire | 87 | yes | not linked |

Argon2 is resolved by the current `crypto` feature even for an Ed25519-only
consumer, while calling salty derivation added 44,442 bytes to this linked
WASM probe. The 25-package core-to-crypto difference includes the signing,
digest and custody graph and must not be attributed solely to Argon2. Since
the Ed25519-only linked artifact omits much of the unused salty path, A17
keeps the existing feature structure rather than adding an unmeasured family
of algorithm/custody feature gates. A26 can revisit finer gates when its
algorithm profile and a concrete downstream WASM budget are known. This
decision preserves the five-crate architecture and does not claim that
dependency compile time is free.
